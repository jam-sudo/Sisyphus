# Holdout Contamination Audit

## Part 0: Overall Contamination Fix Summary

*Updated 2026-04-08 after predictions regeneration and Figure 2 rebuild.*

### Root Cause

76 of 107 holdout drugs were present in the ML Cmax training data (MMPK dataset). The original `mmpk_clean.csv` was built before the holdout set was expanded from 61 to 107 drugs, and the exclusion filter was never re-run.

### Impact

| Metric | Contaminated | Clean | Inflation |
|--------|-------------|-------|-----------|
| ML AAFE | 2.340 | **3.057** | 30.6% better than reality |
| Meta AAFE | 2.283 | **2.808** | 23.0% better than reality |
| Meta %2-fold | 53.3% | **45.8%** | +7.5 pp inflated |
| Engine AAFE | 3.415 | 3.421 | 0.2% (negligible) |
| CL/F AAFE | 3.134 | 3.127 | -0.2% (unaffected) |

The ML track was most affected because the XGBoost model directly memorized holdout Cmax values from training. The engine track was barely affected because it is mechanistic (ADME model predictions are one input among many). CL/F is parameter-free.

### Meta-Learner Weight Shift

| Compound Type | Contaminated | Clean | Interpretation |
|---------------|-------------|-------|----------------|
| Base | w\_eng=0.45, w\_ml=0.55, w\_clf=0.00 | **w\_eng=0.60, w\_ml=0.40, w\_clf=0.00** | Engine regains dominance for bases |
| Non-base | w\_eng=0.00, w\_ml=1.00, w\_clf=0.00 | **w\_eng=0.35, w\_ml=0.50, w\_clf=0.15** | 3-track blend (CL/F now contributes) |

The contaminated meta-learner learned to trust ML almost exclusively (especially for non-base drugs where w\_ml=1.0), because the leaked ML track appeared artificially accurate. Clean meta correctly diversifies across all three tracks.

## Methodology

Three independent exclusion keys are applied to maximise detection coverage:

1. **Canonical SMILES** (`isomericSmiles=True`): exact structural match after RDKit canonicalisation. Catches identical molecules regardless of input notation.

2. **InChIKey prefix (14 chars)**: the first block of the InChIKey encodes connectivity only (ignoring stereochemistry and isotopes). Catches stereoisomers of the same core scaffold. Note: dot-disconnected salts (e.g. `base.Cl`) receive a *different* InChIKey from the free base, so name matching is needed for those.

3. **Lowercase name**: the TDC `Drug_ID` field is compared (lowercased) against the holdout name list. Catches cases where the SMILES differs (salt form, prodrug) but the INN is preserved in the identifier.


All three sets are unioned; a compound is flagged if it matches on **any** key.
