The original framing (deepen the reactive-metabolite/zonal-tox thread by convecting the metabolite downstream) is physiologically wrong for its own use case: a *reactive* metabolite is **consumed locally** (high reactivity → short diffusion length → centrilobular binding — exactly why APAP necrosis is zone-3 and why the B1/GSH-pool **post-processor is the correct model there**). Downstream convection matters only for **stable metabolites that survive transport** — and, since a *well-mixed* active-metabolite species already ships (§2), specifically for a **spatially-resolved** metabolite (per-zone formation + inter-zone convection): zonal exposure of a stable toxic/active metabolite. ## 1. The question

Production already carries a *well-mixed* parent→active-metabolite species (§2), so the question is **composition**: **does the axial machinery (PR #79) compose with that second species — can a metabolite be SPATIALLY RESOLVED across the axial chain (per-zone formation) and CONVECTED inter-zone through a per-zone formation → convection → consumption chain, using graph construction with EXISTING flux types only (zero `src/sisyphus/engine/` change), conserving mass?** And, as the decision payoff: **across the Damköhler number (consumption/transport ratio), when does downstream convection materially move the metabolite's spatial profile versus the local-only post-processor (B1/B1.x)?**

## 2. What is actually under test (and what is not)

**A well-mixed parent → active-metabolite second species already ships in production** (`pipeline/predict.py:48` reads PK "accounting for active species"; `core.py` `active_metabolite`/`conversion_yield_fraction`; the prodrug registry — remdesivir, clopidogrel). So the *basic* multi-species capability — compile a second species into one RHS, form it via `prodrug_activation`, clear it, read its PK — is **already proven**, not the question here. And `transit` with rate `k = Q/V` is **mathematically identical** to flow-convection between well-stirred tanks (both are the `(Q/V)·A` inter-tank transfer the parent axial chain already uses), so transport per se is trivial.

**The genuinely novel question is COMPOSITION: does the axial machinery (PR #79) compose with the active-metabolite species — i.e. can the metabolite be SPATIALLY RESOLVED across the chain (per-zone formation) and CONVECTED inter-zone, rather than living in a single well-mixed pool?** That is what the spike tests:

- **(T1) Axial multi-species compilation.** Does `ODECompiler` assemble a correct single RHS when a *second species' axial chain* (`metabolite__ax1..N`) coexists with the parent's `parent__ax1..N`? (Well-mixed multi-species is production-proven; the *axial* second chain is new.)
- **(T2) Per-zone formation.** Do **N** distinct `prodrug_activation` edges `parent__axi → metabolite__axi` (one per zone) compile — sidestepping the single-target-node "trap" (one edge for the whole organ) by graph construction? (`ProdrugActivationFluxSpec` routes `parent(source) → active(target)` with `mw_active/mw_parent` scaling, drawing on the *source* zone's enzymes — `flux.py:775`.)
- **(T3) Multi-role nodes.** Does a node that is simultaneously a prodrug **target**, a transit **source**, and a consumption **source** compile and solve?
- **(T4) Builder/validation acceptance.** Does the builder accept the metabolite chain topology? (Flow-conservation validation checks only `FlowEdge` in≈out per node, so transit-based convection is not flagged — `body.py:98`; the spike confirms nothing else rejects it.)
- **(T5) Mass conservation.** Does the engine's own `SimResult.mass_balance_error` (and the species-level balance, §4) stay below tolerance for the axial multi-species solve?

The strong YES prior (production already does well-mixed multi-species) means the most likely *failure* mode is specifically in the **axial composition** (e.g. the compiler or builder mishandling a second `__ax` chain), which is exactly what the spike isolates.

**What a YES means precisely — edge-defined species *pools*, not full-ADME species.** The metabolite chain uses **edge-level** kinetics (`transit_rate`, `cl/vd`), not drug-level `fup`/`Kp`/`CLint`. So a YES verdict means the engine can carry **additional species pools whose disposition is specified at the edge level** — which is exactly the active-metabolite-with-literature-CL/Vd case `OneCompartmentEliminationFlux` was built for (its docstring: *"active metabolite clearance where literature reports plasma CL and Vd"* — the engine already anticipates metabolite species, strengthening the feasibility prior). A metabolite carrying **distinct tissue-partitioning / protein-binding** (its own `fup`/`Kp` ≠ parent, driving its own perfusion-limited distribution) is a **separate** capability the engine's single-drug-params state does not provide; the spike **reports** this boundary (a "needs engine support for full multi-species ADME" sub-finding), it does not build it. The convection physics does not depend on molecule-specific params, so this scoping does not weaken the feasibility answer.

## 3. The construction (existing flux types, synthetic skeleton)

A minimal synthetic two-species axial skeleton, built directly via the graph API (the `_axial_graph` pattern), `N` zones inlet→outlet. **All transport/consumption uses edge-level params (verified in `flux.py`), so the metabolite chain is molecule-independent and the Damköhler sweep does not perturb the parent:**
- **parent chain:** a source → `parent__ax1..N` axial convection chain, giving each zone a parent concentration `c_parent,i(t)`. The parent's metabolic loss **is** the `N` prodrug edges below (no separate, redundant parent-clearance edge); unconverted parent exits the axial outlet;
- **formation:** `N` `prodrug_activation` edges `parent__axi → metabolite__axi`, zonatable enzyme (the bioactivation gradient, via `zonation_weights`). **Set `mw_active = mw_parent` and `conversion_yield = 1`** so formation is **1:1 mass-preserving** (`rate_active = rate_parent`) — this makes total mass conserved and the engine's `mass_balance_error` a clean gate (a realistic MW/yield is not needed for the transport question and would muddy the balance);
- **convection:** `N−1` `transit` edges `metabolite__axi → metabolite__ax(i+1)`, `transit_rate = k_conv = Q/V_zone` (edge param; `TransitFluxSpec` adds to the target — genuine convection, `flux.py:410`);
- **consumption:** `N` `one_compartment_elimination` edges `metabolite__axi → metabolite_sink` with `cl_per_h`/`vd_l` set so `k_detox = cl/vd` (edge-level, independent of the parent CLint — `flux.py:896`); a **single shared `metabolite_sink`** node accumulates all eliminated mass for a direct species-level balance;
- **outlet efflux:** `metabolite__axN → metabolite_sink` via a `transit` edge `transit_rate = k_conv`, so metabolite leaving the outlet also lands in the shared sink.

**Damköhler number (chain-level, the reported quantity).** A molecule must survive `N` transit steps to reach the outlet, so the transport timescale is the whole-chain transit time `≈ N/k_conv`. Define `Da ≡ k_detox·(N/k_conv) = N·k_detox/k_conv` — consumption rate × whole-chain transit time. The local↔convective **crossover is then at `Da ≈ 1`** (equivalently per-zone `k_detox/k_conv ≈ 1/N`); `Da ≫ 1` is consumption-dominated (local), `Da ≪ 1` is transport-dominated (convected). The sweep varies `k_detox` (hence `Da`) across the range, holding `k_conv = Q/V_zone` fixed — clean because `k_detox` is an edge param, not the drug CLint. **All regime labels below use this chain-level `Da`.**

## 4. The verdict & pre-registered gates

**A YES verdict requires all of:**
- **G-build/solve (T1–T4):** the chain builds (passes validation), compiles, and solves without any `src/sisyphus/engine/` or builder change. (If not → STOP, "needs engine support" verdict.)
- **G-mass (T5):** two complementary checks. (i) `SimResult.mass_balance_error < tol` (the engine's own global invariant). (ii) A **species-level balance** enabled by the mass-preserving formation + shared sink: at `t_end`, `Σ_i (parent mass converted via prodrug)` ≈ `Σ_i metabolite__axi amount` + `metabolite_sink amount`, to a relative tolerance — i.e. every formed metabolite molecule is either still in the chain or in the sink (nothing leaks).
- **G-convection-correct:** the primary metric is the metabolite profile's **center-of-mass** `⟨z⟩ = Σ_i z_i·∫A_i dt / Σ_i ∫A_i dt` over the **chain zones** `i=1..N` (excluding the shared sink; well-defined since formation is nonzero — peak-zone reported as a coarser secondary). (a) vs a **no-convection control** (`k_conv → 0` on **both** the inter-zone transit **and** the outlet efflux, so the metabolite is fully local — formed + consumed in place, the post-processor analog), the convected `⟨z⟩` shifts **toward the outlet** in the low-Da regime; (b) a **uniform-formation** case in the low-Da regime accumulates monotonically inlet→outlet (plug-flow accumulation).

**The decision map (centerpiece, the payoff).** The Da-map's *qualitative shape* is analytically expected (it is a Damköhler argument, not a discovery); its value is twofold — it **validates that the multi-species engine reproduces the expected transport physics** (a correctness check on T1–T5 across a regime, not a single point), and it pins the **quantitative crossover** that scopes the product decision. Per `Da`, report the center-of-mass shift (convected − local-only):
- **Da ≫ 1 (reactive regime):** shift ≈ 0 — engine and local-only **agree** → **directly validates that the B1/GSH-pool post-processor is correct for reactive metabolites**.
- **Da ≪ 1 (stable regime):** shift is material toward the outlet — the engine captures downstream transport the post-processor misses → where a *spatially-resolved* metabolite earns its complexity. **Honest scope:** this regime is niche (stable zonal-toxic metabolites, e.g. acyl glucuronides; zonal active-metabolite action) — the spike establishes the *capability* and *maps when it matters*, it does not assert a broad product. The common reactive case (high Da) belongs to the post-processor.
- The crossover (chain-`Da ≈ 1`; §3) is **reported, not pre-claimed at an exact value** — the sweep spans well below and above it so the boundary is bracketed.

**Honest-negative paths:** if the construction needs an engine change (STOP verdict), or `mass_balance_error` does not close, or the Damköhler map shows convection never matters even at low Da (would itself be surprising), report as-is. No parameter tuned to force a YES.
